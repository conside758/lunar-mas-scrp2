# 训练接口与算法/模型输入输出梳理

> 本文档梳理两部分：**① 训练接口**（`lunar_env`，Phase 0 已实现，以 `src/lunar_env/lunar_env/env.py`
> 为准）；**② 算法与模型**（Phase 2 设计的 MARL 网络输入输出，待实现）。
> 目标：让「环境返回什么、策略吃进什么、网络吐出什么」一条线对齐，作为 Phase 2 开发的接口契约。

## 1. 训练接口（lunar_env，已实现）

### 1.1 接口契约（Gymnasium）

```python
env = LunarEnv(scenario_file=...)
obs, info = env.reset(seed=None, options=None)            # → (obs, info)
obs, reward, terminated, truncated, info = env.step(action) # → 五元组
env.close()
```

- `reset()`：复位三车位姿（`/gazebo/set_entity_state`）、任务状态（资源量/载量/交付量归零）、
  工具姿态、调用 `/reset_scenario`；返回初始观测。
- `step(action)`：下发动作 → 按 `control_horizon` 推进仿真 → 更新任务状态 → 计算回报 →
  返回下一观测。
- `terminated`：`step_count ≥ max_steps`（时间到）；`truncated` 暂恒为 `False`。

### 1.2 观测空间 `observation_space`（`spaces.Dict`）

| key | 类型 | shape | 含义（逐维） |
| --- | --- | --- | --- |
| `scout` | Box(float32) | `(5,)` | `[x, y, yaw, vx, wz]` |
| `excavator` | Box(float32) | `(6,)` | `[x, y, yaw, vx, wz, bucket]`（bucket=铲斗载量） |
| `hauler` | Box(float32) | `(6,)` | `[x, y, yaw, vx, wz, bin]`（bin=料斗载量） |
| `resources` | Box(float32) | `(n_resources, 3)` | 每行 `[x, y, amount]`（剩余资源量） |
| `depot` | Box(float32) | `(2,)` | `[x, y]`（卸载点） |

- 位姿 `(x,y,yaw)`、速度 `(vx,wz)` 来自 `/gazebo/link_states` 真值（各车 `base_link`）。
- `n_resources` 由 `scenario.yaml` 决定（当前 = 3）。
- 注意：观测是**绝对位姿 + 全局资源表**的“集中视角”，尚未做“以自身为原点的相对/角色编码”
  ——该改造见 §2.4（Phase 2）。

### 1.3 动作空间 `action_space`（`spaces.Dict`，异构）

| key | 子空间 | 含义 |
| --- | --- | --- |
| `scout` | `drive: Box(2, [-1,1])` | `[vx_norm, wz_norm]` 归一化速度 |
| `excavator` | `drive: Box(2, [-1,1])` + `tool: Discrete(3)` | `tool∈{0 idle, 1 dig, 2 load}` |
| `hauler` | `drive: Box(2, [-1,1])` + `tool: Discrete(2)` | `tool∈{0 idle, 1 dump}` |

- `drive[0]*max_lin(=0.4)` → 线速度 m/s；`drive[1]*max_ang(=0.8)` → 角速度 rad/s，发布到
  `/<ns>/cmd_vel`。
- `tool` 映射为关节目标：Excavator 的 `arm_controller/commands`（三关节姿态：idle/dig/load），
  Hauler 的 `dump_controller/commands`（倾卸角度）。

### 1.4 奖励

```python
reward = +bin            # Hauler 在 depot 半径内 dump 时，料斗载量一次性转为交付
         - 0.01 * dt     # 每步时间惩罚
```

- 事件驱动（Phase 0 简化）：`dig` 累加 bucket 并减资源；`load` 在会合半径内转移 bucket→bin；
  `dump` 在 depot 半径内把 bin 计入 delivered 并清零。
- 作业半径/容量/速率见 `scenario.yaml`（`dig_radius/load_radius/dump_radius/bucket_capacity/
  bin_capacity/dig_rate_per_s`）。
- Phase 2 将扩展为带塑形的回报（吸引/错目标/超时/角色级 shaping，见 `docs/训练方案设想.md` §3）。

### 1.5 info

```python
{"delivered": float, "episode_reward": float, "step": int}
```

### 1.6 时序参数（`scenario.yaml → episode`）

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `control_horizon_s` | 0.5 | 每步仿真推进时长（墙钟） |
| `max_time_s` | 120 | 回合时长上限 |
| `max_steps` | 240 | `= max_time_s / control_horizon_s` |

### 1.7 ROS2 桥接（env 内部自建节点 `lunar_env`）

| 方向 | 接口 | 用途 |
| --- | --- | --- |
| 发布 | `/<ns>/cmd_vel` | 三车驱动 |
| 发布 | `/excavator/arm_controller/commands` | 机械臂姿态（Float64MultiArray） |
| 发布 | `/hauler/dump_controller/commands` | 料斗倾卸 |
| 订阅 | `/gazebo/link_states` | 读三车位姿/速度真值 |
| 服务 | `/gazebo/set_entity_state` | reset 复位位姿 |
| 服务 | `/reset_scenario` | reset 复位资源/卸载点 |

## 2. 算法与模型的输入输出（Phase 2 设计）

### 2.1 算法总览（CTDE）

```
集中训练 / 分散执行：
  Actor（每车）  π_i(a_i | o_i)          ← 只用局部观测 o_i
  Critic（全局） V(s) 或 Q(s, a)          ← 用全局状态 s（拼接所有 o_i + 资源 + depot）
```

- **基线（无角色）**：准共享 MAPPO —— 三车共用一个 actor（以角色 one-hot 区分），一个集中 critic。
- **核心（角色感知）**：HAPPO / HASAC —— 三车各一个 actor（异构动作/观测），一个集中 critic；
  加入角色嵌入 + 机器人—资源—队友注意力；同角色多实例才共享参数。

### 2.2 数据流（一步内）

```
env.step 返回 obs(dict)
   │
   ├─ 各车局部观测 o_i  ──► Actor 预处理 ──► 网络 ──► 分布(logits/mean) ──► 采样 a_i
   │                                                        │
   └─ 全局观测 s ─────────► Critic 预处理 ──► 网络 ──► V(s) 标量 ──────────► 计算 GAE/优势
                                                                               │
  动作 a_i 再拼成 env 的 dict action ──► env.step(action)                        ▼
                                                                         PPO 更新（多轮 epoch）
```

### 2.3 Actor 网络输入/输出

**输入（每车，Phase 2 改造后）**：

```
o_i = concat(
  自身:      [x, y, yaw, vx, wz, cargo, role_onehot(3)]      # 8 维
  资源(注意力池化):  Σ softmax(QK)·V   → 定长 d_r              # 变长→定长
  队友(注意力池化):  Σ softmax(QK)·V   → 定长 d_t
  目标点:    [dx_depot, dy_depot, dx_subgoal, dy_subgoal]    # 4 维
)
```

- 角色嵌入：`role_onehot(3)` 经可学习嵌入层后拼入。
- 资源/队友数量可变 → 用**自注意力池化**压成定长（避免按规模分训）。

**输出（按动作子空间分头）**：

| 智能体 | 输出头 | 分布 | 输出维 |
| --- | --- | --- | --- |
| Scout | drive | 高斯（对角） | mean 2 + logstd 2 |
| Excavator | drive + tool | 高斯 + 分类 | mean 2 + logstd 2 + logits 3 |
| Hauler | drive + tool | 高斯 + 分类 | mean 2 + logstd 2 + logits 2 |

- 采样后 `drive` 截断到 `[-1,1]`、`tool` 取 `argmax/采样`，再组装回 env 的 dict action。

### 2.4 Critic 网络输入/输出

**输入（全局状态 s，CTDE 集中 critic）**：

```
s = concat( scout_obs, excavator_obs, hauler_obs, resources.flatten(), depot )
```

- 固定规模下的维度：`5 + 6 + 6 + 3·n_resources + 2`（当前 n_resources=3 → 28 维）。
- 若支持变规模团队/资源：同样用**注意力池化**把各车与资源压成定长后再拼。
- 输出：**1 个标量 V(s)**（PPO 用状态值函数；SAC 则输出 Q(s,a) 需同时吃联合动作）。

### 2.5 维度汇总表（映射到当前 env）

| 对象 | 当前(Phase 0) | Phase 2 改造后 |
| --- | --- | --- |
| Scout 观测 | `(5,)` | `8 + d_r + d_t + 4`（注意力池化后） |
| Excavator 观测 | `(6,)` | `8 + d_r + d_t + 4` |
| Hauler 观测 | `(6,)` | `8 + d_r + d_t + 4` |
| 全局 Critic 输入 | `5+6+6+3·3+2 = 28` | 注意力池化后定长 |
| Scout Actor 输出 | — | `mean(2)+logstd(2)` |
| Excavator Actor 输出 | — | `mean(2)+logstd(2)+logits(3)` |
| Hauler Actor 输出 | — | `mean(2)+logstd(2)+logits(2)` |
| Critic 输出 | — | `1`（V）或 `1`（Q） |

### 2.6 当前(Phase 0) 与计划(Phase 2) 的差异

| 项 | Phase 0（现状） | Phase 2（计划） |
| --- | --- | --- |
| 观测 | 绝对位姿 + 全局资源表 | 相对自身 + 角色 one-hot + 注意力聚合队友/资源 |
| 奖励 | 交付 − 时间 | 增加吸引/错目标/超时/角色级 shaping，分阶段重加权 |
| 动作 | 连续 drive + 离散 tool | 不变（网络加两个输出头） |
| 变长处理 | 固定 `n_resources` | 注意力池化支持变资源/变团队 |
| 算法 | 无（随机策略） | MAPPO 基线 + HAPPO/HASAC 核心 + 消融 |
