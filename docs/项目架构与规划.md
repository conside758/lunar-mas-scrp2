# 月球多智能体协同采矿系统 —— 项目文档

> 基于 NASA Space Robotics Challenge Phase 2（SCRP2）简化规则的异构多机器人协同采矿项目。
> 技术栈：ROS2 Humble + Gazebo classic 11 + Python 3.10。
> 本文档更新于 Phase 0 完成之后。

---

## 1. 项目概述

### 1.1 背景与动机

月球资源勘察、月壤挖掘与物料运输对机器人结构与能力的要求明显不同：

| 角色 | 能力要求 |
| --- | --- |
| 侦察车 Scout | 高移动速度 + 资源/地质探测能力 |
| 挖掘车 Excavator | 机械臂、铲斗/挖掘机构 |
| 运载车 Hauler | 大承载能力 + 稳定往返运输 |

单一机器人难以同时高效完成上述任务，一旦故障还会中断整条采矿流程。因此采用
**Scout + Excavator + Hauler 异构团队**，通过角色分工完成连续采矿任务。

### 1.2 任务流程

在机器人数量、任务时间、能源、运输容量与通行代价有限的约束下，对三车进行
动态任务分配、路径规划与作业调度，连续完成：

```
资源确认 → 挖掘车调度 → 运载车调度 → 挖掘装载 → 运输卸载
```

### 1.3 方法创新点

现有空间采矿系统主要依赖**规则状态机**；通用 MAPPO 稳定性好但难以表达明显的
**角色异构**；HAPPO/HATRPO/HASAC 等异构算法尚未应用于采矿任务中特有的
「机器人—资源—队友」关系。

**项目目标**：构建一种**角色感知的异构多智能体强化学习方法**，使 Scout / Excavator /
Hauler 能在固定采矿任务中自主学习**目标选择、跨角色会合与任务接力**，并适应不同
机器人数量与资源分布。以 HARL 框架的 HAPPO / HASAC 为基础，引入角色嵌入与
机器人—资源—队友注意力。

### 1.4 阶段划分

- **第一阶段（Stage 1）**：假设月表物理特性/通行代价已知，训练三车完成协同采矿闭环。
- **第二阶段（Stage 2）**：取消「通行代价已知」假设，由**腿式 Scout** 主动探索与
  感知未知月表物理特性，建立共享作业物理特性地图，并预测重型机器人（空/满载运载车、
  挖掘车）的作业风险。侦察车腿部后续加装地质探测传感器。

## 2. 项目架构

### 2.1 技术栈

| 项 | 选型 |
| --- | --- |
| 中间件 | ROS2 Humble |
| 仿真器 | Gazebo classic 11.10（`gazebo_ros` / `gazebo_ros2_control`） |
| 控制框架 | ros2_control（`diff_drive_controller`、`joint_state_broadcaster`、`position_controllers/JointGroupPositionController`） |
| 建模 | 自建简化 URDF/xacro（不依赖外部开源模型） |
| 训练接口 | Gymnasium（`lunar_env` 包装 ROS2/Gazebo） |
| 强化学习 | HARL（HAPPO / HASAC）——Phase 2 引入 |
| 语言 | Python 3.10（高层）、CMake（消息接口包） |

### 2.2 系统分层（数据自下而上）

```
┌─────────────────────────────────────────────────────┐
│ 决策层  规则基线策略（Phase1） + MARL 策略（Phase2）      │
│         （通过同一训练接口驱动任务层，可无缝切换与对比）      │
├─────────────────────────────────────────────────────┤
│ 任务层  任务分配 / 调度 / 会合状态机（lunar_task）        │
├─────────────────────────────────────────────────────┤
│ 训练接口层  lunar_env：Gymnasium 封装 obs/action/reward │
├─────────────────────────────────────────────────────┤
│ 感知层  Scout 资源探测 / 资源地图（lunar_perception）     │
├─────────────────────────────────────────────────────┤
│ 控制层  ros2_control 差分驱动 / 机械臂 / 腿关节 / 料斗     │
├─────────────────────────────────────────────────────┤
│ 仿真层  通用世界 + 三台自建机器人 + 资源区 + 卸载点        │
└─────────────────────────────────────────────────────┘
```

### 2.3 包结构

| 包 | 职责 | 类型 |
| --- | --- | --- |
| `lunar_msgs` | 自定义 msg / srv / action 接口 | ament_cmake |
| `lunar_descriptions` | 三台机器人 URDF（xacro）+ 传感器挂载点 | ament_cmake |
| `lunar_gazebo` | 通用世界、spawn/launch 脚本 | ament_cmake |
| `lunar_control` | ros2_control 控制器 YAML + Scout 步态节点 | ament_python |
| `lunar_perception` | 资源探测服务 + rviz 可视化标记 | ament_python |
| `lunar_task` | 资源管理器（resource_manager）+ 任务状态机（Phase1） | ament_python |
| `lunar_env` | Gymnasium 环境封装 + 随机策略冒烟脚本 | ament_python |
| `lunar_bringup` | 顶层 launch + 场景配置（scenario.yaml） | ament_python |
| `lunar_utils` | 指标记录（MetricsLogger） | ament_python |

### 2.4 机器人模型（自建简化）

- **Scout（腿式）**：4 腿 × 2 关节（髋俯仰 + 膝）= 8 DOF，足端球面接触 + 高摩擦；
  `scout_gait` 节点用对角小跑驱动 8 关节，暴露 `cmd_vel`；**每只足端预留
  `geology_sensor_frame` 挂载点**（Stage 2 地质传感器）。
- **Excavator（挖掘车）**：4 轮差分底盘 + 3 DOF 平面机械臂（肩/肘/腕俯仰）+ 铲斗；
  具备「挖掘 / 装载」动作，铲斗容量 `bucket_capacity`。
- **Hauler（运输车）**：4 轮差分底盘 + 料斗 + 倾卸关节（绕 y 轴后倾）；具备
  「接载 / 运输 / 卸载」动作，料斗容量 `bin_capacity`。

统一：`base_link → odom` TF、碰撞/惯性、`robot_state_publisher`、ros2_control 控制器。

### 2.5 任务模型（SCRP2 简化）

- 资源抽象为「资源区 + 单位资源量（units）」，不做真实颗粒/挥发分仿真。
- 约束：时间预算、能量预算、料斗/铲斗容量。
- 评分（全局回报）：`+交付单位数`，减 `行驶距离/时间`、`能耗`、`碰撞`、`任务失败`。
- 动作语义（Phase 0，任务级）：
  - Scout：`drive=[vx,wz]`（探测在感知层隐式完成）
  - Excavator：`drive=[vx,wz]` + `tool∈{idle,dig,load}`
  - Hauler：`drive=[vx,wz]` + `tool∈{idle,dump}`

### 2.6 关键接口

- **ROS2 话题**：`/allocation/tasks`、`/resources`、`/depot`、`/<ns>/cmd_vel`、
  `/<ns>/joint_states`、`/gazebo/link_states`（位姿真值）。
- **服务**：`/reset_scenario`、`/detect_resources`、`/gazebo/set_entity_state`。
- **训练接口**：`lunar_env` 提供 `reset()/step()/observation_space/action_space`，
  动作/观测为异构 `gymnasium.spaces.Dict`；reset 复位机器人位姿 + 任务状态。

## 3. 技术路线

```
Phase 0（已完成）   环境 + 机器人 + 训练接口就绪
   └─ 自建三车模型 + 通用世界 + ros2_control + lunar_env

Phase 1（下一步）   规则基线闭环
   └─ 规则/启发式任务分配 + 会合/装卸状态机，跑通完整采矿闭环并录指标

Phase 2（方法核心） 角色感知异构 MARL
   └─ HAPPO/HASAC + 角色嵌入 + 机器人—资源—队友注意力；与规则基线、无角色 MAPPO 消融

Phase 3（后续）     第二阶段 + 腿传感器
   └─ 未知月表物理特性感知 + 共享风险地图 + 重型机器人风险预测 + 月面环境切换
```

**方法路线决策**（已确认）：先做**规则基线**（验证仿真与任务流、提供对照与回报信号），
再以 HAPPO / HASAC 做**角色感知 MARL**；机器人采用**自建简化模型**；初期里程碑为
**环境 + 机器人 + 训练接口就绪**。

**关键架构决策**：
- 决策动作采用**高层任务级离散动作**（选资源、会合、挖掘、运输、卸载），底层由控制层
  闭环执行——与 odt「目标选择、跨角色会合、任务接力」一致，便于 MARL 接入。
- 机器人数量**可配置**（初期 1 Scout + 1 Excavator + 1 Hauler），接口按 N/M/K 扩展。
- 每台机器人**独立 namespace**（`/scout`、`/excavator`、`/hauler`）+ 共享任务总线。
- 时钟统一 Gazebo `/clock` + `use_sim_time`，训练按固定物理步长推进。

### 4.2 关键工程问题（均已解决，详见 `docs/SETUP.md`）

1. 无头环境 NVIDIA GLX 上下文创建失败 → 改用 Mesa 软件渲染。
2. `~/.ros`、`~/.local`、`/opt`、`/var/crash` 只读 → `ROS_HOME` 指向工作空间、
   `gymnasium` 装入 `pylib/`。
3. ament_python 缺 `setup.cfg` 导致可执行文件装错目录 → 补 `setup.cfg`（libexec）。
4. gazebo_ros2_control 架构：外部 `ros2_control_node` 无法加载 `GazeboSystem` →
   改用插件内部 controller_manager + `<parameters>` 通配 YAML（`/**/`）+ spawner。
5. `<state_interface>` 应为 `<command_interface>` 的**兄弟**元素（非子元素）。
6. 系统 `gazebo_ros2_control 0.4.10` 存在多实例命名空间「错位一位」bug（官方
   PR #398 修复）→ 从源码构建含修复版本做 overlay。
7. spawn 与 spawner 需**完全串行**，避免共享 rcl 全局参数（控制器 YAML 路径）竞态。

### 4.3 遗留问题（Phase 1 处理）

- 车轮方向反向：正 `linear.x` 时倒退（需交换左右轮名或翻转关节轴向）。
- Scout 步态稳定性：对角小跑参数需调稳，必要时改三足爬行/引入 IK。

## 5. 下一步计划

### Phase 1 —— 规则基线闭环（近期）

1. **运动修正**：修车轮方向反向；调稳 Scout 步态（振幅/抬膝/频率参数，必要时爬行步态）。
2. **规则基线任务层**：在 `lunar_task` 实现就近拍卖式任务分配 + 会合/装卸状态机：
   - Scout 探测并按价值排序资源 → 指派最近 Excavator → Hauler 会合 → 挖掘装载 →
     运输卸载 → 状态回传；含超时重派与失败重试。
3. **闭环打通**：三车自主完成 ≥1 次完整采矿闭环，用 `lunar_utils.MetricsLogger`
   记录交付量、耗时、能耗、碰撞等指标，形成后续 MARL 的对照基线。
4. **验收**：规则基线交付量 > 0 且指标可复现。

### Phase 2 —— 角色感知异构 MARL（方法核心）

1. 接入 HARL 的 HAPPO / HASAC（异构 actor、顺序更新、同角色可参数共享）。
2. 角色感知增强：角色嵌入 + 机器人—资源—队友注意力；CTDE（集中训练/分散执行）。
3. 训练与调参，做消融：**角色感知 HAPPO vs 规则基线 vs 无角色区分 MAPPO**。
4. 验收：MARL 交付量 ≥ 规则基线，且消融显示角色感知优于无角色区分。

### Phase 3 —— 第二阶段 + 腿传感器（后续）

1. 取消「通行代价已知」假设，接入未知月表物理特性感知。
2. Scout 主动探索（速度/扭矩/转向/重复碾压），建立共享作业物理特性地图。
3. 预测空/满载运载车与挖掘车的作业风险，并反馈更新。
4. 侦察车足端 `geology_sensor_frame` 加装地质探测传感器；切换月面仿真环境。
