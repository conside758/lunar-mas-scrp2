## 1. Phase 0 收尾（遗留，优先级最高）

> 阻塞 P1/P2，先修完才能做“真正可控”的闭环与训练。

1. **修车轮方向反向**
   - 现象：Excavator/Hauler 正 `linear.x` 时倒退。
   - 修法（二选一）：交换 `excavator_controllers.yaml` / `hauler_controllers.yaml` 中
     `left_wheel_names` 与 `right_wheel_names`；或在 URDF 翻转车轮关节轴向。
   - 验收：`ros2 topic pub /excavator/cmd_vel ... {linear:{x:0.5}}` 后 `gz model -m excavator -p` 的 x 增大。

2. **调稳 Scout 步态**
   - 现状：`scout_gait.py` 对角小跑关节空间近似，参数未调稳。
   - 修法：先调 `hip_amplitude / knee_lift / stance_knee / step_freq_per_ms`；不稳则改三足爬行，
     必要时引入 2 连杆 IK 做足端轨迹跟踪。
   - 验收：Scout 在 `cmd_vel` 下能持续前进/转向不翻倒。

## 2. Phase 1 —— 规则基线闭环

3. **（含 §1 的运动修正）**

4. **`lunar_task` 规则基线实现**
   - 就近拍卖式任务分配：Scout 探测并按价值排序资源 → 指派最近 Excavator → Hauler 会合 →
     挖掘装载 → 运输卸载 → 状态回传。
   - 会合/装卸状态机 + 超时重派与失败重试。

5. **跑通完整闭环 + 指标记录**
   - 三车自主完成 ≥1 次「资源确认→挖掘→装载→运输→卸载」。
   - 用 `lunar_utils.MetricsLogger` 记录：交付量、完成时间、能耗、碰撞、失败次数。

6. **验收**：规则基线交付量 > 0，指标可复现；作为 MARL 的对照下界与示范来源。

## 3. Phase 2 —— 角色感知 MARL

> 网络结构细节以 `docs/训练接口与模型输入输出.md` 为准；奖励/课程/评估以
> `docs/训练方案设想.md` 为准。

7. **reward 改造（`lunar_env`）**
   - 落地：`Δdelivered + 吸引(接近) − 步进 − 错目标 − 超时`，分阶段重加权开关。
   - 追加：势函数形式的角色级 shaping（Scout 发现、Excavator 装载、Hauler 交付）。

8. **观测改造（`lunar_env`）**
   - 落地：角色 one-hot + 相对资源/队友/depot/子目标 + 变长**注意力池化**。

9. **训练脚手架**
   - 实现：准共享 MAPPO（无角色基线）+ 角色感知 HAPPO/HASAC（核心）。
   - 关键件：CTDE、GAE/优势、策略熵、集中 critic、异构 actor（高斯 drive 头 + 分类 tool 头）。
   - 参考论文（已入库 `docs/papers/2604.01213_*.pdf`）的 CTDE 与异构编码。

10. **课程与示范初始化**
    - C0（单 Hauler 卸载）→ C1（挖装运卸）→ C2（加探测调度）→ C3（变规模 + 动态重规划）。
    - 用 Phase 1 规则基线的 rollout 做 behavior cloning 预热。

11. **评估脚本**
    - 四组对比：规则基线 / 无角色 MAPPO / 角色感知 MAPPO / 角色感知 HAPPO+HASAC。
    - 多种子 + N/M/K 规模 + 资源分布随机 + 动态重规划（新资源/资源耗尽/队友故障）。

12. **消融报告与验收**
    - 消融：角色共享 vs 不共享、有无角色嵌入、有无注意力、有无角色级 shaping。
    - 验收（统计显著）：角色感知 HAPPO/HASAC 交付量 ≥ 规则基线，且 ≥ 无角色 MAPPO。
