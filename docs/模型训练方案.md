## 1. 总览

- **算法框架**：CTDE（集中训练、分散执行）下的**异构 MAPPO**——**每车一个独立 Actor** +
  一个**集中 Critic**（观察全局 96 维），共享回报，GAE + PPO-clip，逐 Agent 更新。
- **训练载体**：快速替身环境 `SurrogateEnv`（纯 Python 运动学模型，与 `lunar_env` 同接口，
  毫秒级/回合，供离线训练），训练后策略无缝迁移到 `lunar_env` 做 Gazebo 验证。
- **预热手段**：规则基线策略做 **BC / DAgger** 预热 Actor + **蒙特卡洛回报预拟合 Critic**，
  再低学习率 RL 微调。
- **当前阶段**：Stage 2（资源位置未知），Scout 靠探测发现资源、Excavator 只用已发现资源、Hauler
  运输卸载（三车功能角色已闭环）。Stage 1（资源位置已知）作为对照已跑通。

```
[规则基线 rollout] ──BC/DAgger──► [Actor 预热]
                                        │
                          [Critic 预热（MC 回报）]
                                        │
                          [MAPPO 微调（GAE + PPO-clip）]
                                        │
                          [确定性评估（交付量）]  →  迁移到 Gazebo 验证
```

## 2. 任务设计

### 2.1 机器人角色（3 台，自建简化模型）

| 名称 | 角色 | 运动 | 工具（离散） |
| --- | --- | --- | --- |
| scout | 探测（Stage 2：探索并发现未知资源） | 四腿（步态） | 无 |
| excavator | 挖掘 | 2 轮差分 | 0=空闲 / 1=挖掘 / 2=装载 |
| hauler | 运输 | 2 轮差分 | 0=空闲 / 1=卸载 |

- **任务链**：Excavator 到资源区 → 挖掘（铲斗）→ 满斗后与 Hauler 会合 → 装载到车斗 →
  Hauler 运到 depot → 卸载交付。Scout 在 Stage 1 只朝最近资源巡视（无实际贡献）。
- **目标**：最大化 240 步内的累计交付量 `delivered`。

### 2.2 回合参数（来自 `scenario.yaml` 的 `episode`）

| 参数 | 值 | 含义 |
| --- | --- | --- |
| `max_time_s` | 120.0 | 回合时长 |
| `control_horizon_s` | 0.5 | 控制周期 → **240 步/回合** |
| `dig_radius` | 0.6 | 挖掘判定半径 |
| `load_radius` | 0.7 | 装载判定半径 |
| `dump_radius` | 0.7 | 卸载判定半径 |
| `detect_radius` | 1.5 | Scout 探测半径（Stage 2：进入此半径的资源被标记「已发现」） |
| `bucket_capacity` | 4.0 | 铲斗容量 |
| `bin_capacity` | 10.0 | 车斗容量 |
| `dig_rate_per_s` | 2.0 | 挖掘速率（单位/s） |

- 资源：3 个（id 0/1/2，amount 20/15/25，位置见 `scenario.yaml`）；depot 坐标 (-2.0, -1.5)。
- 运动学模型（`SurrogateEnv`）：`vx = max_lin·vx_norm`（max_lin=0.4）、`wz = max_ang·wz_norm`
  （max_ang=0.8），`x += vx·cos(yaw)·dt` 等，**无碰撞/打滑**。

### 2.3 课程阶段（`stage`）

| stage | 内容 | 用途 |
| --- | --- | --- |
| `c0` | Hauler 预装货（车斗=容量）且资源清空 → 只练「去 depot 卸载」 | 验证单一 go-to-goal + dump |
| `c1` | 仅保留资源 0 → 单链「挖掘→装载→运输→卸载」 | 验证完整单链 |
| `c2`/`full` | 全资源 + Scout 巡视 | 完整任务 |

## 3. 观测空间（Observation）

### 3.1 原始 obs（`SurrogateEnv._obs()` 返回的 dict）

```python
obs = {
  "scout":     np.array([x, y, yaw, vx, wz]),                 # 5 维
  "excavator": np.array([x, y, yaw, vx, wz, bucket]),         # 6 维（cargo=铲斗量）
  "hauler":    np.array([x, y, yaw, vx, wz, bin]),            # 6 维（cargo=车斗量）
  "resources": np.array([[x, y, amount] × n]),               # (n,3)
  "depot":     np.array([x, y]),                              # 2 维
  "goals":     {"scout":[gx,gy], "excavator":[gx,gy], "hauler":[gx,gy]},  # 各车当前子目标
}
```

### 3.2 每车编码向量（`obs.encode_obs`，**32 维**）

| 段 | 内容 | 维数 |
| --- | --- | --- |
| 自身 | `[x, y, yaw, cargo]`（不含 vx/wz，替身与 Gazebo 速度不一致，去掉以免 OOD） | 4 |
| 角色 one-hot | `[scout, excavator, hauler]` | 3 |
| 相对 depot | `[depot_x−x, depot_y−y]` | 2 |
| 相对最近**已发现**资源 | `[dx, dy, amount]`（未发现时置零） | 3 |
| 相对所有资源展平 | `[dx,dy,amount] × n`（n=3，未发现资源置零） | 9 |
| **资源发现掩码** | `[d0,d1,d2]`（哪些资源已由 Scout 发现） | 3 |
| 相对所有队友展平 | `[dx,dy] × 2` | 4 |
| 相对当前子目标（世界系） | `[gx−x, gy−y]` | 2 |
| 相对当前子目标（**车体系**） | 旋转 `−yaw` 后的 `[dx,dy]` | 2 |

- **车体系子目标是关键**：`[dx·cos(yaw)+dy·sin(yaw), −dx·sin(yaw)+dy·cos(yaw)]`。
  它免去网络做「世界系目标角 − 车航向」的带环绕角度减法，使 go-to-goal 可被回归学习
  （此前 BC 转向符号都学反，改后 BC 从 0 直接到满分）。
- **Stage 2（资源未知）**：观测只暴露「已发现」资源（未发现的位置与量都置零），并附发现
  掩码；Excavator 只能挖已发现资源，Scout 靠探测把资源逐步加入观测。
- 变规模时（资源数/队友数不固定）将改用注意力池化或 top-K 排序（尚未实现）。

### 3.3 全局输入（集中 Critic）

`encode_global` = 拼接三车编码向量 = **96 维**（= 3 × 32）。

## 4. 动作空间（Action）

`action` 为 dict，每车一个子 dict：

```python
action = {
  "scout":     {"drive": [vx_norm, wz_norm]},                 # 连续，无 tool
  "excavator": {"drive": [vx_norm, wz_norm], "tool": 0|1|2}, # 连续 + 3 类离散
  "hauler":    {"drive": [vx_norm, wz_norm], "tool": 0|1},   # 连续 + 2 类离散
}
```

| 分量 | 类型 | 取值范围 | 说明 |
| --- | --- | --- | --- |
| `drive` | 连续（高斯） | `[-1,1]²` | 归一化前进/转向，env 内乘 `max_lin`/`max_ang` |
| `tool` | 离散（分类） | 见上 | excavator {0,1,2}；hauler {0,1}；scout 无 |

- 训练采样：`drive ~ N(mean, std)`（可学习 logstd），`tool ~ Categorical`。
- 确定性评估：`drive=mean`、`tool=argmax`。

## 5. 模型结构（网络）

### 5.1 Actor（每车独立，`networks.Actor`）

```
输入: 该车编码向量 (obs_dim=32)
  → Linear(32→128) → Tanh → Linear(128→128) → Tanh  (独立主干)
  ├─ drive_mean  = Linear(128→2)                       # 连续驱动均值
  ├─ drive_logstd = Parameter(2,)  初值可配            # 连续驱动对数标准差
  └─ tool_logits = Linear(128→3)                       # 工具 logits（excavator 用 3 类，hauler 用前 2 类）
```

- **结构**：`actors = {"scout": Actor, "excavator": Actor, "hauler": Actor}`，三个独立网络、
  各自参数，消除角色间梯度干扰与容量共享。
- 观测统一 32 维（含角色 one-hot，对独立 Actor 属冗余但无害，暂保留；vx/wz 已从观测去掉；
  新增资源发现掩码 3 维）。
- `drive_logstd` 初值：`-0.7`（std≈0.50，探索）/ `-2.0`（std≈0.14，细调微调）。
- `std = exp(logstd).clamp(min=1e-3)`。

### 5.2 Critic（集中，`networks.Critic`）

```
输入: 全局编码 (global_dim = 3×obs_dim = 96)
  → Linear(96→128) → Tanh → Linear(128→128) → Tanh → Linear(128→1)  # 输出标量 V(s)
```

### 5.3 异构程度的现状与规划（重要）

**普通 Actor 基线只是「参数级异构」，不是「结构/角色感知级异构」**（角色感知/HAPPO 已实现，见下方
「要补的异构」清单——②③ 已 ✅ 完成）：

| 维度 | 现状 |
| --- | --- |
| 参数 | 3 个 Actor 完全独立、各自权重、各自只用自己角色的数据训练 → **隐式角色专精**（挖掘车 actor 学会挖/装，运输车 actor 学会运/卸） |
| 动作空间 | tool 头结构上都是 3 维，但有效类别数不同（scout 0 / excavator 3 / hauler 2） |
| 角色 one-hot | 仍在观测里，但**已冗余**——每个 actor 只处理自己角色，它的角色 one-hot 是常量（共享 Actor 时代的遗留），不提供信息 |
| 观测结构 / 隐层 / drive 头 | 完全相同（都是 32 维、128 隐层、2 维 drive）→ 结构同构 |

**HAPPO/HASAC 阶段要补的「真正异构」：**
1. **角色专属观测**（scout 无 cargo，各车特征不同）；
2. **角色嵌入 + 对资源/队友的注意力**（robot-resource-teammate relations，项目方法核心创新）——
   ✅ 已实现 `RoleAwareActor`（`networks.py`）：对 3 个资源实体 + 2 个队友实体做 dot-product 注意力池化，
   替代扁平 rel_res/team_rel 拼接；`train.py` 加 `--role-aware` 开关。替身 Stage 2 交付 36.0，
   与普通 Actor 基线（32~36）持平；
3. **异构训练动力学**（逐 Agent 信任域、顺序更新等 HAPPO 机制）——
   ✅ 已实现：`mappo.py` 的 `MAPPO` 加 `hap` 参数；`hap=True` 时顺序更新（逐 Agent 独立优化器 +
   各自 ratio 裁剪信任域，每 Agent 独立前向），`hap=False` 时为原 MAPPO 同时更新；`train.py` 加
   `--hap` 开关。
   ✅ **HAPPO 多智能体优势（反事实基线，2026-09-13 修正）**：补齐了先前只有「顺序更新」而缺
   的 HAPPO 核心——反事实优势。`networks.py` 新增 `QCritic`（Q(s, a)）与 `encode_joint_action`
   （把 3 车 drive(6) + 挖掘 one-hot(3) + 运输 one-hot(2) 编成 11 维联合动作）；`hap=True` 且
   带 `QCritic` 时，逐 Agent 优势改为 **A_i = Q(s, a) − Q(s, a_cf_i)**（a_cf_i = 第 i 个 agent
   换成其均值 drive + argmax tool），并对每个 agent 单独归一化；`warmup_critic` 同时预热 V(s) 与
   Q(s,a)。这是角色感知 HAPPO 的关键：共享优势（MAPPO）会把信用错配到注意力结构上，反事实基线
   逐 agent 拆开贡献后，RoleAwareActor 不再被 RL 洗掉（见 §9 消融）。

### 5.4 HASAC（异构角色 Soft Actor-Critic，`hasac.py`）

与 HAPPO 的「策略梯度 + 反事实优势」不同，HASAC 走 **Soft Actor-Critic（SAC）** 路线，三处异构扩展：

1. **3 个逐 Agent 软 Q Critic**：`Q_i(s, a_i)` 输入全局状态 s（96 维）+ 自身动作 a_i（drive 2 +
   tool one-hot k，`AGENT_ACTION_DIM`），输出该 agent 的动作价值；各 agent 一个独立 Q 网络 + 目标网络
   （soft 更新 τ）。
2. **熵正则价值目标**：软 Bellman 备份 `y_i = r_i + γ(1-done)(Q_targ_i(s',a'_i) − α·log π_i(a'_i|o'_i))`；
   策略目标最小化 `J_i = E[α·log π_i(a|o) − Q_i(s,a)]`。drive（连续）用重参数化采样，tool（离散）用
   精确期望 `Σ_t p_t·Q(s,[drive, onehot_t])`。
3. **逐角色奖励 shaping**：`surrogate.per_agent_reward` 把共享回报拆成「团队项(deliver+step) + 角色
   专属项 + 自身吸引」——Scout 拿探测、Excavator 拿挖掘+装载、Hauler 拿装载，各自只用自身 reward 更新
   自己的 Critic/Actor。

> 训练入口 `train_hasac.py`（回放缓冲 + 离线更新），支持 `--role-aware`/`--kl-coef`（BC 参考策略 KL
> 锚）/`--reset-std`/`--alpha`/`--critic-lr`。实测（§9.1）：在本「近确定性精修」场景里，SAC 的熵最大化
> 目标会持续漂移策略，稳定性不如 HAPPO 反事实——这是算法机制差异，非实现缺陷。

### 5.5 变规模观测 + 角色感知注意力（`obs.encode_obs_vars` + `VarRoleAwareActor`）

固定场景的观测把资源/队友**展平成定长向量**（32 维，3 资源 2 队友），无法表示「资源/队友数量变化」。
为做变规模/动态重规划应力测试，引入**实体化观测 + 掩码注意力**：

- **可变实体编码**（`encode_obs_vars`）：每车 = 固定特征 `fixed`(13: self+role+depot+子目标) + 资源实体
  `res_ent`(max_res×4: [dx,dy,amount,detected]) + 队友实体 `team_ent`(max_team×2) + 有效掩码。未发现资源
  整行置零（隐藏位置与量），Scout 的探索方向由 `fixed` 里的显式子目标提供。
- **`VarRoleAwareActor`**：对资源/队友实体做**掩码 dot-product 注意力**池化——置换不变、实体数无关，
  天然支持任意 ≤max 的实体数；普通 `FlatActor`（= `Actor` + `flat_vars` 展平定长）作为对照。
- **`SurrogateEnv` 变规模/动态**：`scenario_var.yaml`（资源池 8 个，每回合采样 3~6 个）、
  `scenario_dyn.yaml`（初始 3 个量小资源，耗尽后从池中重生、需重新探测）。
- 训练/对比入口 `train_vars.py`（规则示范 BC + 同种子对比评估）。结果见 §9.2——**这是「角色感知 ≥ 无
  角色」真正成立的地方**（固定场景压不出注意力优势，变规模/动态重规划压出来了）。

**关于「角色感知」的正确含义（澄清）：**

角色功能是固定且互斥的——Scout 只探测、Excavator 只挖掘、Hauler 只运输，**探测只属于 Scout，
不存在「谁发现了什么资源」的区分**。角色感知真正指的是**各角色专属的 robot-resource-teammate 关系**：

```
Scout      ──注意──► 资源（找「未发现」的）          [探测/探索关系]
Excavator  ──注意──► 「已发现」资源 + Hauler         [挖掘关系 + 会合关系]
Hauler     ──注意──► Excavator + depot               [会合关系 + 卸载关系]
```

- 关系是**按角色划分**的：每个角色的注意力只关注「对它的角色有意义」的实体。
- 共享的「资源发现状态」（`detected` 掩码）是信息流：Scout 的探测**写入**它，Excavator **读取**
  它来决定去哪挖。角色感知要建模的是「各角色如何消费这份共享状态、各自关注哪类关系」，
  而不是「谁发现的」。

## 6. 奖励设计（`rewards.py` + `surrogate._update_task`）

### 6.1 奖励分量（`DEFAULT_WEIGHTS`）

| 分量 | 权重 | 公式 | 触发条件 |
| --- | --- | --- | --- |
| `deliver` 交付 | 1.0 | `+ w·bin` | Hauler `tool=1` 且在 `dump_radius` 内且 `bin>0` |
| `dig` 挖掘 | 0.5 | `+ w·gain` | Excavator `tool=1` 且在 `dig_radius` 内有量资源 |
| `load` 装载 | 0.5 | `+ w·transfer` | Excavator `tool=2` 且与 Hauler 距 `< load_radius` |
| `detect` 探测 | 1.0 | `+ w`（一次性） | Scout 进入 `detect_radius` 发现一个新资源（Stage 2） |
| `app` 吸引 | 1.0 | `+ w·(prev_dist − dist)` | 各车接近其当前子目标（势函数近似） |
| `step` 步进 | 0.02 | `− w·dt` | 每步（≈ −0.01/步） |

- `dig` 速率 `gain = min(dig_rate·dt, bucket_capacity−bucket, amount)`；
  `load` 转移 `transfer = min(bucket, bin_capacity−bin)`。
- 奖励在 `_update_task` 中按分量累加，`info["reward_breakdown"]` 暴露 `dig/load/deliver/app/step`
  五项，用于诊断。

### 6.2 势函数塑形与目标切换修正

- `app` 是**势函数近似**：只奖励「接近目标」的过程（`prev_dist − dist`），
  不会奖励「停在目标旁」（静止时差值为 0）。
- **目标切换修正**：`goal_key_for()` 返回每车目标的「身份」键（如 hauler 空→`"excavator"`、
  有货→`"depot"`）。目标身份变化时**重置势能基线**，避免虚假的势能跳跃。

### 6.3 子目标 `goal_for`

| 机器人 | 空/不满 | 满/有货 |
| --- | --- | --- |
| excavator | 最近**已发现**资源 | Hauler 位置（去装载） |
| hauler | Excavator 位置（去会合） | depot（去卸载） |
| scout | 最近**未发现**资源（去探索） | depot（都发现后） |

## 7. 算法（MAPPO，`mappo.py`）

### 7.1 训练要素

- **CTDE**：集中 Critic 看全局（96 维）；执行时各车只用自身编码（32 维）+ 自己的 Actor。
- **共享回报**：每步一个标量奖励，三车共享。
- **逐 Agent ratio**：PPO 更新时每个 Agent 用自己的 logprob 比值 `ratio_i`，与**共享优势**相乘，
  `policy_loss = −mean(min(ratio_i·adv, clip(ratio_i)·adv))`（对步与 3 个 Agent 取均值）。
- **GAE**：`γ=0.99, λ=0.95`，优势做标准化。
- **PPO-clip**：`clip_eps=0.2`，多 epoch（4），`value_coef=0.5`，`entropy_coef=0.001`，
  梯度裁剪 0.5。
- **优化器**：`Adam(所有 actors 参数 + critic 参数, lr)`（`lr` 默认 3e-4，微调用 1e-4~3e-5）。

### 7.2 超参数汇总

| 参数 | 值 | 备注 |
| --- | --- | --- |
| γ (gamma) | 0.99 | 可 `--gamma` 调整 |
| λ (gae_lambda) | 0.95 | |
| clip_eps | 0.2 | |
| entropy_coef | 0.001 | 可 `--entropy-coef` |
| value_coef | 0.5 | |
| epochs | 4 | |
| 隐藏层 | 128 | Actor/Critic 同 |
| drive_logstd 初值 | −0.7 / −2.0 | 探索 / 细调 |
| 梯度裁剪 | 0.5 | |

### 7.3 预热（`bc.py` + `mappo.warmup_critic`）

1. **BC**：规则策略 rollout → `(obs_batch, drive, tool)` 数据集 → 监督学习
   （drive 用 MSE，tool 用交叉熵）。
2. **DAgger**：迭代「当前策略 on-policy rollout → 专家(规则)重标注 → 增广数据 → 再训练」，
   修复复合误差。当前 sweet spot ≈ 4 轮（更多轮反而退化）。
3. **Critic 预热**：用与 rollout 一致的**随机采样**做蒙特卡洛回报，预拟合 Critic，
   避免随机 critic 早期产生噪声优势、洗掉 BC 策略。
4. **KL 防漂移正则**（`--kl-coef > 0` 时启用）：对 BC 参考策略（DAgger 后的 **actors 深拷贝字典**）
   逐 Agent 加 KL 惩罚——drive 用均值 L2 距离、tool 用分类 KL，防止 RL 微调把好策略洗掉。

**HASAC（离线 SAC，`train_hasac.py`）**：


### 8.2 关键参数

| 参数 | 含义 |
| --- | --- |
| `--stage` | c0/c1/c2/full |
| `--seed` | 随机种子（RL 采样/批序；BC checkpoint 独立于该种子） |
| `--bc-episodes` / `--bc-epochs` | BC 数据量 / 轮数 |
| `--dagger-rounds` | DAgger 迭代轮数（0=普通 BC） |
| `--critic-warmup` | RL 前预拟合 critic 的回合数（hap 时同时预热 QCritic） |
| `--std-init` | drive logstd 初值 |
| `--lr` / `--gamma` / `--entropy-coef` | 训练超参 |

| `--app-weight` | 覆盖吸引奖励权重（微调时可调低降回报方差） |

| `--hap` | HAPPO：顺序更新 + 反事实优势 A_i=Q(s,a)−Q(s,a_cf_i)；缺省=MAPPO 同时更新 |
| `--domain-rand` | 训练时对速度/转向做域随机 |
| `--load-actor` | 从已有 checkpoint 预热 actor/critic（含 qcritic） |
| `--iters` / `--steps` / `--eval-every` | RL 迭代数 / 每轮 rollout 步数 / 评估频率 |

### 8.3 课程链

`train_curriculum.py` 按 `c0 → c1 → c2 → full` 逐级：加载上轮 checkpoint → BC/DAgger →
critic 预热 → 低 lr RL 微调 → 保存本级 checkpoint。

### 8.4 Gazebo 内 BC/DAgger 管线（消除 sim-to-sim 迁移差距）

替身训练的 go-to-goal 迁移到 Gazebo 会失效（转向动力学差异 + BC 平滑「原地转向」），因此
改为**在 Gazebo 里直接收集规则示范训练**，从根上消除差距：

1. **收集规则示范**（launch `eval_mode:=collect`）：`collect_gazebo_data.py` 在 Gazebo 里跑
   规则基线，逐步存 `(encoded_obs, rule_drive, rule_tool)` 到 `.pkl`。
2. **DAgger 采集**（`eval_mode:=dagger`）：`collect_dagger_gazebo.py` 加载当前 BC checkpoint，
   on-policy 滚动并把访问状态按规则重标注，存到新 `.pkl`。
3. **训练**：`python3 -m lunar_rl.train_gazebo_bc <data.pkl> <out.pt> --epochs N`，合并多份
   数据后 `train_bc`，保存 3-actor checkpoint。
4. **评估**：`eval_mode:=policy`（`run_policy.py` 加载 checkpoint 跑 240 步）。

实测：4 回合 BC → 0.0（停在卸载点外 ~1m）；+3 轮 DAgger（样本 960→1440→1920→2400）→
交付 8.0 → 14.0 → 14.0（收敛，落在规则基线现场噪声区间 10~22 内）。

## 9. 当前结果与验收（历史基线 2026-08-31；HAPPO/角色感知最新消融见 §9.1）

| 阶段 | 规则基线 | 学习策略 | 备注 |
| --- | --- | --- | --- |
| c0 | 10.0 | BC=10.0；RL 从零=10.0 | ✅ 达基线 |
| c1 | 20.0 | BC=20.0 | ✅ 达基线 |
| full | 44.0 | DAgger-BC=36~40（82~91%） | ✅ 接近基线 |
| full | 44.0 | BC+RL 微调（全 app 权重）8~32 振荡 | ⏳ 不稳定 |
| full | 44.0 | BC+RL 微调（app 降到 0.3）稳定 ≈26 | ⏳ 稳定但低于 BC |
| **Stage 2（未知资源）** | 44.0（替身规则） | DAgger-BC=**32~36**（8 轮） | ✅ 规则基线跑通、Scout 探测必要（不动时 0）；4 轮 DAgger 仅 12~21，**8 轮达 32~36（与 Stage 1 的 36~44 基本持平）** |

- **当前最佳学习策略 = DAgger-BC**，作为 MAPPO 基线的实际承载。重构为 3 个独立 Actor 后：
  c0/c1 仍精确达基线（10/20），full 阶段 DAgger-BC 跨种子 24~36（seed 3 达 36，与重构前
  36~40 同一量级，属 DAgger 随机性，无系统性退化）。
- **RL 微调现状**：降低 `app` 权重能显著降低回报方差 → critic 变准（warmup loss 14→0.3）、
  交付量从不稳定振荡变为稳定（≈26），但首次更新仍会跌破 DAgger-BC，随后在较低水平稳定
  （RL 在噪声下优化「鲁棒性」而非「确定性最优」）。根因是交付量指标对微小扰动**不连续**。
- **Gazebo 迁移验证（2026-09-05）**：canonical seed3 策略（替身 36）在 Gazebo 仅 4.0；
  依次尝试「观测改指令速度（更差，已回退）」「域随机（仍打转）」「原地转向 go_to max(0,cos)²
  （v3，仍 0）」「去观测速度 vx/wz（v4，仍 0）」，规则基线同场 10~22（历史记录 16）。
- **转向动力学实测（turn_test）**：纯转向（vx=0, wz=0.8）效率 **≈50%**（excavator 52%、
  hauler 49%）；而「边前进边转向」效率骤降到 ~8~13%。即**纯转向并不慢，慢的是边转边走**。
- **根因定位（精化）**：策略用 BC/DAgger 学 go-to-goal，会把「背对目标时原地转向（vx=0）」
  平滑成「vx≈0.1~0.3 慢速前进 + 转向」，恰好落入 Gazebo 里最差的「边转边走」区间，于是
  缓慢画圈、无法会合。这是 **BC 对硬阈值/尖锐非线性回归的固有平滑问题**，与替身动力学假
  设叠加导致迁移失败。
- **结论与验证（Gazebo 内 BC + DAgger 已跑通，收敛到 14.0）**：替身训练的 v3/v4 在 Gazebo
  均 0；改用 **Gazebo 内直接收集规则示范做 BC（4 回合）** 后策略能走完「挖→装→运」但停在
  卸载点外 ~1m（0.0）；补 **DAgger 三轮**（每轮 2 回合 on-policy 重标注，样本 960→1440→
  1920→2400）后交付量 **8.0 → 14.0 → 14.0（收敛）**。**Gazebo 内 BC + DAgger 是消除
  sim-to-sim 差距的有效路径**；14.0 已落在规则基线现场噪声区间（10~22）内、逼近历史记录 16，
  后续微调（更多 DAgger 或 RL 精修）可再逼近。

**验收标准**：① MAPPO 基线交付量 ≥ 规则基线（替身 44/full，Gazebo 16/240 步）；
② 角色感知 HAPPO/HASAC ≥ 无角色 MAPPO（统计显著）；③ Gazebo 迁移验证 + 消融报告。

### 9.1 HAPPO 反事实基线消融（2026-09-13/14，5 种子 seed 1~5，替身 Stage 2）

> 配置：从 BC 预热 checkpoint（`stage2_bc8.pt` / `stage2_ra.pt`）低 lr RL 精修，
> `--std-init -2.0 --kl-coef 2.0 --app-weight 0.3 --gamma 0.9 --lr 3e-5 --iters 60
> --critic-warmup 20`；HAPPO 单元（B/D）的 QCritic 用 `--critic-lr 3e-4`（actor 仍 3e-5）。
> 评估 10 回合取均值（替身确定性，逐次一致）。checkpoint：`.tmp/ms_s{1..5}_{A,B,C,D}*.pt`
> （A/C 的 seed3 沿用 `.tmp/abl_{A,C}_*.pt`）。

| 单元 | Actor | 训练动力学 | s1 | s2 | s3 | s4 | s5 | 均值 ± std |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| A（无角色 MAPPO 基线） | 普通 Actor | MAPPO 同时更新（共享 GAE 优势） | 44.0 | 36.0 | 36.0 | 44.0 | 44.0 | 40.80 ± 4.38 |
| B | 普通 Actor | HAPPO 顺序 + 反事实优势 | 28.0 | 36.0 | 36.0 | 36.0 | 36.0 | 34.40 ± 3.58 |
| C（角色感知 MAPPO） | RoleAwareActor | MAPPO 同时更新 | 28.0 | 22.0 | 30.0 | 36.0 | 27.0 | 28.60 ± 5.08 |
| **D（角色感知 HAPPO）** | RoleAwareActor | **HAPPO 顺序 + 反事实优势** | **36.0** | **36.0** | **36.0** | **36.0** | **36.0** | **36.00 ± 0.00** |
| E | 普通 Actor | HASAC（逐 Agent 软 Q + 熵正则 + 逐角色 shaping） | 32.0 | 36.0 | 36.0 | 36.0 | 20.0 | 32.00 ± 6.93 |
| F（角色感知 HASAC） | RoleAwareActor | HASAC（同上） | 36.0 | 26.0 | 32.0 | 26.0 | 24.0 | 28.80 ± 5.02 |

**显著性（Welch t 检验，双侧）：**

| 对比 | 均值差 | t | p | 结论 |
| --- | --- | --- | --- | --- |
| D vs C（同 RA：反事实 HAPPO vs MAPPO） | 36.00 vs 28.60 | 3.258 | **0.0011** | 反事实显著修复角色感知 ✅ |
| D vs A（角色感知 HAPPO vs 无角色 MAPPO） | 36.00 vs 40.80 | −2.449 | **0.0143** | 严格「≥」**未达成**（A 显著更高）⚠️ |
| A vs C | 40.80 vs 28.60 | 4.067 | <0.001 | 无角色 MAPPO 显著高于 RA+MAPPO |
| B vs A | 34.40 vs 40.80 | −2.530 | 0.0114 | 反事实对普通 Actor 反而略差 |

- **核心结论 ①（方法有效，强）**：反事实基线把 RoleAwareActor 从 C 的 **28.60**（22~36，被 RL 洗掉）
  拉回 D 的 **36.00（0 方差，5 种子全 36）**，p=0.0011。共享优势会把信用错配到注意力结构上；逐
  agent 反事实优势 A_i=Q(s,a)−Q(s,a_cf_i) 拆开贡献后 RA 不再被洗掉。旧版「只有顺序更新、无反事实」
  的 RA+HAPPO 仅 20.0 —— 反事实是本方法生效的关键。
- **核心结论 ②（对基线，未严格达标）**：**角色感知 HAPPO（D=36.0）显著低于无角色 MAPPO（A=40.8，
  p=0.014）**。原因不是 HAPPO 差，而是**普通 Actor + MAPPO 在本固定场景里把 BC 从 36 改进到了 44
  （5 种子中 3 次）**，而 RoleAwareActor 只能回到 BC 水平（36）、无法再往上。即：固定 3 车/3 资源
  场景**压不出注意力的优势**，注意力反而成了更难的优化问题。
- **反例（B）**：普通 Actor + 反事实 HAPPO（34.40）略低于普通 Actor + MAPPO（40.80，p=0.011）。
  共享优势对无需角色异构信用分配的普通 Actor 本就够用，反事实 Q 反而引入方差——**反事实不是无脑
  更好，而是专门修复角色异构信用分配**（正是项目方法针对的问题）。
- **QCritic 独立 lr 的必要性**：seed3 的 B 在 `--critic-lr 3e-4` 下从旧结果 24.0 回到 36.0，说明
  反事实 Q 需要比 actor（3e-5）更高的学习率才能跟住回报；已加 `--critic-lr` 开关。
- **HASAC（E/F）结论**：普通 Actor+HASAC=32.0、RA+HASAC=28.8，**均低于 HAPPO 反事实（B=34.4 / D=36.0）**，
  且方差更大。机制原因：SAC 的熵最大化离线目标 `α·log π − Q` 会**持续漂移**近确定性策略（policy_loss
  不为 0），而 HAPPO 反事实优势在 a≈a_cf 时自然趋于 0 → 几乎不更新、天然冻结 BC 策略。即 HASAC 三件套
  （逐 Agent 软 Q + 熵正则 + 逐角色 shaping）已实现，但**在本「近确定性精修」场景不如反事实 HAPPO**；
  其优势（探索/离线样本效率）应在「从零训练 / 强探索」场景才体现。
- **对后续的指导**：要让「角色感知 ≥ 无角色」成立，需要**能压出注意力价值**的场景——变规模
  （资源/队友数不固定）、动态重规划（新资源/资源耗尽/队友故障），或角色专属观测。在固定场景里
  角色感知只能「不输在 RL 洗掉」，无法「赢」。→ 已用 §9.2 的变规模/动态场景验证。

### 9.2 变规模/动态重规划应力测试（2026-09-14，规则示范 BC，3 训练种子 × 20 评估回合）

> 配置：`scenario_var.yaml`（资源池 8，每回合采样 3~6 个资源，耗尽重生）/ `scenario_dyn.yaml`
> （初始 3 个量小资源，耗尽后重生需重新探测）；规则示范 BC（`train_vars.py`），同评估种子对比
> `VarRoleAwareActor`（掩码注意力）vs `FlatActor`（展平定长 + 掩码）。规则基线：变规模 ≈64.4、动态 ≈38。

| 场景 | 数据量 | VarRoleAwareActor | FlatActor | 结论 |
| --- | --- | --- | --- | --- |
| 变规模（3~6 资源） | 20 回合 BC | **29.5**（3/3 种子胜） | 12.3 | 注意力样本效率显著占优 |
| 变规模（3~6 资源） | 60 回合 BC | 36.1（19.4~51.4） | 30.2（28.7~31.9） | 差距缩小、种子 1 反超 |
| 动态重规划（重生） | 60 回合 BC | **25.3±6.5**，重规划事件 **1.1** | 12.9±6.2，重规划事件 0.2 | 注意力能重新探索/重规划 |

- **核心结论（BC 层面）**：**角色感知注意力在变规模/动态重规划场景确实优于展平 Actor**，具体体现在
  ① **样本效率**（20 回合 BC 下 29.5 vs 12.3，3 种子全胜，展平在数据充足时才能追上）；
  ② **动态重规划**（资源耗尽重生后，注意力策略能重新探测新资源并续挖——重规划事件 1.1 vs 0.2，
  交付 25.3 vs 12.9）。这正好补上了固定场景里「注意力不占优」的缺口：**注意力为「变规模泛化 +
  动态重规划」买单**。
- **RL 精修（HAPPO 反事实 / MAPPO，从 60 回合 BC 精修，seed 0/1/2，`train_vars_rl.py` + `mappo_vars.py`）**：

  | 单元 | Actor | 算法 | s0 | s1 | s2 | 均值 ± std |
  | --- | --- | --- | --- | --- | --- | --- |
  | G 角色感知 HAPPO 反事实 | VarRoleAwareActor | HAPPO 顺序 + 反事实 | 19.9 | 3.8 | 26.8 | 16.8 ± 12.0 |
  | H 无角色 MAPPO | FlatActor | MAPPO 共享优势 | 35.1 | 28.2 | 30.1 | 31.1 ± 3.6 |

  **RL 精修不稳定、反而洗掉 BC**：G 从 BC 均值 36.1 跌到 16.8（seed1 甚至 3.8），H 基本持平 BC（31.1 ≈ 30.2）。
  即：变规模场景回报方差更大 → QCritic 噪声更大 → 反事实优势漂移策略；注意力结构对 RL 漂移更敏感，
  「展平+共享优势（MAPPO）」反而更稳。**里程碑 ② 在变规模 + RL 精修下仍未达成**（16.8 < 31.1）。
  - 改进尝试（调研后）：**Cal-QL 式保守 Q**（`--cql-coef`，Q 对 OOD 均值动作加惩罚）能部分降退化——
    seed0 19.9→35.8（coef 1.0），但种子相关、seed2 略降、对已崩 seed1 无效；**RLPD 式预填**对 HASAC
    无帮助。详见 `docs/调研-离线微调与MaxEntMARL.md` §五。
- **结论**：角色感知注意力的价值**在 BC/模仿层面**（样本效率 + 动态重规划），不在「RL 精修稳定性」；
  RL 精修洗掉 BC 是本项目一直未解的瓶颈（与 §9.1 固定场景一致），注意力结构放大了这一漂移。

### 9.3 6 机器人任务选择场景（2026-09-20，`scenario_6r.yaml`）

> 6 机器人（scout×2/excavator×2/hauler×2）+ 2 depot + 8 异构资源（水冰 value 3 / 钛铁矿 value 2 /
> 月壤 value 1，总价值 233）；限时 120s 逼出「选哪个资源/哪个 depot」。规则基线 = 拍卖 bid=value/(1+distance)。

| 方案 | delivered_value（/233） |
| --- | --- |
| 规则基线（拍卖） | 191.0 |
| **角色感知 BC** | **143.0** |
| 展平 FlatActor BC | 24.0 |
| 角色感知 HAPPO 反事实精修 | 118.0（CQL+KL 稳住，但低于 BC） |

- **正**：角色感知注意力在任务选择场景远超展平（143 vs 24）。
- **负**：RL 精修（HAPPO 反事实）仍无法改进 BC（118 < 143，不加固直接坍缩到 0）——「RL 洗 BC」瓶颈在
  6 机器人场景重现且更严重。
- **⚠ 逻辑口径（待补对照）**：`scenario_6r` 相对旧 3 机器人场景同时改了机器人数(3→6)、资源数(3→8)、
  资源总量(60→151)、价值(1→1/2/3 异构)、depot(1→2)，故「143 vs 24」**混杂了「更多实体/更难场景」与
  「任务选择」两因素**，不能直接归因于「任务选择」。需加对照（同实体规模下「均匀价值+单 depot」vs
  「异构价值+双 depot」）才能干净隔离「任务选择」这一变量。
