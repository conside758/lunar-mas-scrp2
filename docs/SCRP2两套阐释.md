# NASA Space Robotics Challenge Phase 2（SCRP2）规则的两套阐释

> 一份面向**审稿人**（科研问题定义，论证研究价值），一份面向**开发**（工程实现规格，
> 把复杂任务压缩为可实现的算法框架）。
> 事实依据：NASA Centennial Challenges 官方规则与参赛论文
> （[arXiv:2109.09620](https://arxiv.org/abs/2109.09620)、
> [Frontiers in Robotics and AI, 2023](https://www.frontiersin.org/journals/robotics-and-ai/articles/10.3389/frobt.2023.1149080/full)）。

---

## 0. 比赛规则要点（事实依据）

SCRP2 是在 Gazebo 虚拟月面环境中进行的**全自主多机器人挑战**，114 支队伍参赛、6 支晋级。
三台异构机器人：**Scout（侦察/探测，携 2 m 范围挥发分传感器）、Excavator（挖掘，机械臂+铲斗）、
Hauler（运输，带料斗）**。资格赛三项任务：

| 任务 | 内容 | 评分依据 |
| --- | --- | --- |
| Task 1 资源探测 | 用 Scout 探测并识别随机分布的 28 处挥发分，报告位置 | 位置误差 ≤ 2 m 计分 |
| Task 2 挖掘装载 | 资源位置预先给出，Excavator 挖掘、倒入 Hauler 料斗 | 挥发分全部入料斗计分 |
| Task 3 目标定位 | 报告随机 CubeSat 位置，并返回处理厂对齐 | 位置误差 ≤ 5 m 计分 + 对齐 |

关键约束（决定问题难度的来源）：

1. **无 GPS/信标** —— 无全局定位，只能靠本体传感器；
2. **无地面通信** —— 运行中完全自主，无人干预；
3. **传感器受限** —— 耦合的有限视距 LiDAR + 立体相机；低纹理、暗弱、含永久阴影区，VO 易漂移；
4. **地形恶劣** —— 陡坡、打滑、岩石、陨石坑；
5. **短程探测** —— 挥发分只有 Scout 能测、且仅 2 m 范围；
6. **随机化** —— 障碍、资源位姿、初始位姿、CubeSat 每个仿真种子都随机；
7. **时限** —— 单次 45 分钟。

> 完整赛程还包括**决赛**：把资源运到**处理厂（processing plant）**交付（而不只是入料斗），
> 与本项目「运输卸载」闭环一致。

## 1. 阐释一：面向审稿人的科研问题定义

### 1.1 一句话定位

在**能力异构、感知受限、通信受限、环境随机**的约束下，研究**异构多机器人如何在共享
物理场中通过角色分工与自主接力完成长链条的 ISRU 任务**，核心科学问题落脚于
**「角色感知的异构多智能体协同决策」**。

### 1.2 问题形式化（Dec-POMDP）

把 SCRP2 抽象为一个**异构去中心化部分可观测马尔可夫决策过程（heterogeneous Dec-POMDP）**：

- **智能体集合**：$\mathcal{A}=\{\text{Scout},\text{Excavator},\text{Hauler}\}$，各自
  **动作空间 $\mathcal{A}_i$、观测空间 $\mathcal{O}_i$、动力学/载荷/能力都不同**——
  这是与同质多智能体（共享一套策略）的本质区别。
- **状态** $s$：全局月面状态 = 机器人位姿 + 资源分布 + 地形/物理特性 + 任务进度。
- **观测** $o_i$：局部、带噪声（无 GPS、VO 漂移、短程探测），且**角色间观测异构**——
  Scout 能看资源、Excavator 能看土层、Hauler 只能看路径。
- **联合策略** $\pi=(\pi_{\text{S}},\pi_{\text{E}},\pi_{\text{H}})$，目标为最大化
  带约束的累计回报（交付量 − 时间/能耗/失败代价）。
- **核心挑战**：异构信用分配（credit assignment）——「Scout 探测 → Excavator 挖掘 →
  Hauler 运输」是一条**跨角色的时序因果链**，Hauler 的失败可能源于 Scout 的探测，
  共享回报难以归因；以及**跨角色会合（rendezvous）与任务接力（task relay）**的协同。

### 1.3 研究价值论证（为什么值得做）

1. **从同质到异构多智能体协同的关键一跃**：绝大多数 MARL 工作假设同质智能体 + 参数
   共享；SCRP2 天然给出「能力互补、观测/动作空间异构」的真实任务，是检验**异构 MARL**
   的试金石。对应方法缺口——通用 MAPPO 稳定但无法表达角色异构，HAPPO/HATRPO/HASAC 能
   处理异构策略但未在「机器人—资源—队友」耦合任务上验证。
2. **共享物理场的序贯耦合**：采矿不是并行独立子任务，而是**严格先后、跨角色传递资源**
   的接力链（探测→调度→会合→装载→运输），比取放、追逐等典型基准更能暴露
   **时序信用分配与接力规划**问题。
3. **感知受限下的决策**：无 GPS + 漂移 + 2 m 短程探测，把「先感知、后决策」的耦合带进
   问题，而非假设全知状态——更贴近真实星球探测。
4. **可泛化与可扩展性**：机器人数量（N 台 Scout / M 台 Excavator / K 台 Hauler）与资源
   分布可变，直接对应「异构团队规模自适应」这一开放问题。
5. **第二阶段（本研究延伸）**：取消「通行代价已知」假设，由**腿式 Scout 本体感知**
   （轮速、电流、姿态、运动响应）估计月表物理特性、为重型机器人做风险迁移预测——把
   「主动感知 + 风险地图 + 协同决策」闭环，属于 terramechanics × 多机器人决策的前沿交叉。

### 1.4 研究空白与本文切入点

- 现有空间采矿工程**依赖规则状态机**，缺乏学习性与鲁棒性；
- 通用 MAPPO **不能充分表达角色异构**；
- HAPPO 系异构算法**尚未在「资源—机器人—队友」三元关系**上应用；
- 因此本文提出**角色感知的异构多智能体强化学习（role-aware heterogeneous MARL）**：
  以 HAPPO/HASAC 为基，加入**角色嵌入（role embedding）**与**机器人—资源—队友注意力**
  （robot–resource–teammate attention），显式建模接力链中的角色分工与协作关系。

### 1.5 可发表的贡献点

1. **形式化**：把 SCRP2 简化为异构 Dec-POMDP，给出统一的任务/角色/奖励抽象；
2. **方法**：角色感知异构 MARL（角色嵌入 + 三元注意力），在 HAPPO/HASAC 上扩展；
3. **实证**：与规则基线、无角色 MAPPO、无角色感知消融对比，证明角色感知带来
   交付量与鲁棒性的显著提升；
4. **环境/基准**：开源 ROS2 + Gazebo 的多机器人采矿环境与训练接口，作为社区基准；
5. （第二阶段）**本体感知风险迁移**：腿式 Scout 的地形物理特性估计到重型车作业风险的
   迁移，形成「感知—地图—决策—反馈」闭环。

### 1.6 可能质疑与回应

- *「这只是一个仿真比赛」* → 仿真提供可复现、可量化的异构协同基准，且无 GPS/无通信/
  随机化/时限约束逼近真实任务；结论以算法框架与可迁移接口为主，不宣称物理实验。
- *「与单机器人导航/抓取相比创新在哪」* → 创新在**跨角色接力与异构信用分配**，而非单点
  感知或控制；用「去掉角色感知」的消融直接证明贡献。
- *「简化后是否仍是 SCRP2」* → 保留三车异构、任务链条、随机化与评分精神，仅在初期用
  通用环境与已知代价降门槛；第二阶段逐步补回未知地形与本体感知。

## 2. 阐释二：面向开发的工程实现规格

> 目标：把「探测→调度→会合→挖掘→装载→运输→卸载」的复杂任务，压缩为**一个可训练、
> 可评估、可扩展的算法框架**，用最小可运行闭环支撑 MARL 迭代。

### 2.1 系统分解（谁做什么）

| 层 | 组件 | 职责 | 接口 |
| --- | --- | --- | --- |
| 仿真层 | Gazebo 世界 + 3 URDF | 物理/碰撞/传感器真值 | `link_states`、spawn |
| 控制层 | ros2_control | 差分驱动/机械臂/腿/料斗 | `cmd_vel`、关节命令 |
| 感知层 | 探测服务 | 资源探测（带噪声） | `detect_resources` |
| 任务状态层 | resource_manager | 资源量、载量、交付量（权威状态） | `resources`、`reset_scenario` |
| **决策层** | **策略（规则/MARL）** | **每步输出各车动作** | `step(actions)` |
| 训练接口 | `lunar_env`（Gymnasium） | 统一 obs/action/reward/reset | `reset()/step()` |

### 2.2 任务抽象（把复杂任务压成算法框架的关键化简）

1. **资源离散化**：把「连续挥发分分布」抽象为**有限个资源区**，每个有
   `(id, 位姿, 剩余量, 价值)`——不仿真颗粒/挥发分物理，只保留「还有多少可挖」。
2. **作业离散化**：挖掘/装载/卸载由**半径判定 + 单位速率**建模（在资源区半径内且选
   `dig` → 按速率转移单位量），不仿真真实铲斗/土力学。
3. **通行代价参数化**：第一阶段代价已知（距离/坡度/打滑抽象为地图代价），第二阶段用
   Scout 本体感知在线更新——为两阶段留同一个接口。
4. **动作任务级化**：决策层只输出**任务级动作**（去哪个资源/会合谁/挖/运/卸），
   底层导航与操作由控制器闭环执行——把「连续控制 + 规划」从强化学习问题中剥离。

### 2.3 决策接口（MDP/Dec-POMDP 落地规格）

**动作空间**（每车异构）：

```
Scout     : drive=[vx, wz]
Excavator : drive=[vx, wz], tool∈{idle, dig, load}
Hauler    : drive=[vx, wz], tool∈{idle, dump}
```

**观测空间**（每车异构 + 共享）：

```
scout      : [x, y, yaw, vx, wz]                     # 自身位姿/速度
excavator  : [x, y, yaw, vx, wz, bucket]             # + 铲斗载量
hauler     : [x, y, yaw, vx, wz, bin]                # + 料斗载量
resources  : [(x, y, amount) × N]                    # 共享资源地图
depot      : [x, y]                                  # 共享卸载点
```

**状态转移与事件**（在 env 内部按 `control_horizon` 推进）：

```
dig    : Excavator 距资源区 < dig_radius 且 tool=dig  → bucket += rate·dt，resource.amount -= …
load   : Excavator 距 Hauler < load_radius 且 tool=load → bucket → bin（受 bin_capacity 限制）
dump   : Hauler 距 depot < dump_radius 且 tool=dump     → delivered += bin，bin = 0
```

### 2.4 奖励设计（共享 + 可分解）

```
r = +λ_delivered · Δ(delivered)                    # 交付单位
    − λ_time · dt                                  # 时间/能耗
    − λ_collision · 碰撞                           # 可选
    − λ_fail · 任务失败/超时                        # 可选
```

- 全局共享主回报保证「整条接力链」同目标；Phase 2 再加**角色级 shaping**（Scout 奖励
  发现资源、Excavator 奖励装载、Hauler 奖励交付）缓解稀疏与信用分配。
- 终端：`max_steps = max_time_s / control_horizon_s` 或全部资源耗尽。

### 2.5 训练与评估协议

1. **基线先行**：规则基线（就近拍卖分配 + 状态机）跑通闭环，作为对照与回报下界。
2. **MARL**：HAPPO/HASAC 异构 actor（同角色内可参数共享、跨角色独立），CTDE；
   角色嵌入 + 机器人—资源—队友注意力。
3. **评估指标**：交付单位、任务完成时间、能耗、失败/碰撞次数、团队规模鲁棒性
   （N/M/K 变化）、资源分布鲁棒性（多随机种子）。
4. **消融**：角色感知 HAPPO vs 无角色 MAPPO vs 规则基线；有无角色级 shaping。
5. **验收**：MARL 交付量 ≥ 规则基线，且角色感知 > 无角色区分（统计显著）。

### 2.6 实现路线（与项目 Phase 对齐）

| Phase | 交付 | 验收 |
| --- | --- | --- |
| **P0（已完成）** | 环境 + 3 机器人 + 控制器 + `lunar_env` | `colcon build` 干净、无头 launch、随机策略不崩 |
| **P1** | 修车轮方向/步态；规则基线闭环；指标记录 | 完整采矿闭环 + 可复现指标 |
| **P2** | 角色感知 MARL（HAPPO/HASAC）+ 消融 | MARL ≥ 基线，角色感知 > 无角色 |
| **P3** | 第二阶段：未知地形 + 腿传感器 + 风险地图 | 感知→决策→反馈闭环 |

### 2.7 简化边界与风险

- **边界**：资源/作业离散化、通行代价已知（P1）、无真实挥发分物理、无真实通信约束
  （默认不限带宽）——这些是「降门槛」而非「去难度」，第二阶段逐步回填。
- **风险**：① Scout 腿式步态不稳 → 降幅/改爬行/引入 IK；② 稀疏回报导致学不动 →
  用规则基线的 rollout 做课程学习/示范初始化；③ 异构信用分配难 → 角色级 shaping +
  注意力结构 + 消融验证；④ sim 随机性与 reset 一致性 → 固定种子 + 真复位 + 多次取均值。
