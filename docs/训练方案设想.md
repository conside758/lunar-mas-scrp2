# 训练方案设想 —— 参考《Collaborative Task and Path Planning for Heterogeneous Robotic Teams using Multi-Agent PPO》

> 参考论文：Matthias Rubio, Julia Richter, Hendrik Kolvenbach, Marco Hutter（RSL, ETH Zürich），
> [arXiv:2604.01213](https://arxiv.org/abs/2604.01213)，代码
> [github.com/leggedrobotics/multi_robot_global_planner](https://github.com/leggedrobotics/multi_robot_global_planner)。
>
> 本文档给出**借鉴该论文、面向本项目 Phase 2（MARL 模型训练）的设想方案**，重点解决
> 三个问题：① 稀疏回报如何塑形；② 异构角色如何编码；③ 训练如何冷启动与逐步加难。

---

## 1. 论文方法定位与可借鉴点

### 1.1 论文做了什么（摘要）

用 **MAPPO + CTDE** 协调「带技能集合的异构团队」，在离散网格上做目标分配 + 调度 + 路径
规划；动作空间 `{up,down,left,right,stay}`，目标有技能需求（OR 型单技能可解 / AND 型多技能
协作可解）；对照穷举搜索最优解并验证在线重规划。

### 1.2 五条可直接借鉴的要素

| 论文要素 | 说明 | 映射到本项目 |
| --- | --- | --- |
| **异构能力编码** | 智能体/目标的技能集合用 multi-hot 编码进观测 | 角色 one-hot/multi-hot 编码（SCOUT/EXCAVATOR/HAULER） |
| **CTDE** | 集中 critic 拼接全员观测，分散 actor | HAPPO/HASAC 的集中 critic（含全局资源+队友信息） |
| **奖励塑形** | AR（吸引）+ TR（目标）+ WC（错目标）+ SC（步进）+ TC（耗时）+ BR（完成） | 见 §3，解决挖矿任务「交付才有回报」的稀疏问题 |
| **课程式训练** | 预训练（易探索）+ 精调（重加权压低 AR） | 见 §5，先短链条后加会合/接力/规模 |
| **评估协议** | 对照最优/经典规划器 + 在线重规划 + 多规模 | 对照规则基线 + 多随机种子 + N/M/K 扩展 + 动态重规划 |

### 1.3 角色定位（本方案如何用这篇论文）

这篇论文的 actor 是「技能无关、可套用到任意智能体」的**准共享**策略，恰好对应本项目的
**「无角色区分」基线**。本项目的核心创新是**角色感知**（不共享），因此：

- **用它做消融基线**：准共享 MAPPO（无角色感知）——验证「角色感知 > 无角色」。
- **借它的配方**：奖励塑形、异构编码、课程训练、评估协议，直接复用到 HAPPO/HASAC 上。
- **不做的事**：不照搬离散网格与 5 动作（本项目是连续 drive + 离散 tool）；不采用按目标数
  分训（本项目用注意力处理变长资源与变规模团队）。

## 2. 总体训练框架

```
for episode in 1..E:
    obs = env.reset(seed)                        # 复位位姿/资源/载量
    for t in 1..T:
        a_i ~ pi_i(obs_i)                        # 各车独立决策（分散执行）
        obs', r, done = env.step({a_i})
        存 (o, a, r, o', done, 全局状态) 到 buffer
    # 集中训练（CTDE）
    用 buffer 更新 critic（拼接全局观测/状态）
    用 buffer 更新 actor（仅用局部观测）
```

- **基线（无角色）**：准共享 MAPPO —— 三车共用一个 actor 网络（以角色 one-hot 为输入），
  集中 critic 拼接全员观测。对应论文的「技能无关 actor」。
- **核心（角色感知）**：HAPPO / HASAC —— 每车独立 actor（异构动作/观测空间），集中 critic；
  加入**角色嵌入 + 机器人—资源—队友注意力**；同一角色多实例时才做参数共享。

## 3. 奖励设计（借鉴论文 AR/TR/WC/SC/TC/BR）

把论文的塑形项映射到「探测→调度→会合→挖掘→装载→运输→卸载」链条：

$$
r = \underbrace{\lambda_{deliver}\,\Delta \text{delivered}}_{\text{TR/BR：交付单位}}
  + \underbrace{\lambda_{app}\,h(\text{到下一目标距离})}_{\text{AR：接近/吸引}}
  - \underbrace{\lambda_{step}\,dt}_{\text{SC：步进}}
  - \underbrace{\lambda_{wrong}\,\mathbf{1}[\text{错目标作业}]}_{\text{WC}}
  - \underbrace{\lambda_{timeout}\,\mathbf{1}[\text{任务超时/失败}]}_{\text{TC}}
$$

逐项定义（`lunar_env` 内实现）：

| 项 | 含义 | 具体规则 |
| --- | --- | --- |
| `Δdelivered` | 交付单位 | Hauler 在 depot 半径内 `dump`，`bin→delivered`，主回报 |
| `h(·)` | 吸引/接近 | 对「当前任务的下一目标」（资源区/会合点/depot）按指数衰减 `exp(-c·d)`，仅当该目标仍需要该角色时发放 |
| 步进 | 时间/能耗 | 每步 `-λ_step·dt` |
| 错目标 | 惩罚 | Excavator 在非指派资源区 `dig`、Hauler 过早 `dump` 等 |
| 超时 | 失败 | 任务超时、碰撞、能耗耗尽 |

**分阶段重加权（借鉴论文「预训练 + 精调」）**：

1. **预训练期**：`λ_app` 较大（引导各车学会导航与接近），`λ_deliver` 正常；
2. **精调期**：`λ_app` 逐 epoch 衰减，`λ_deliver`、`λ_timeout` 主导，迫使完成整条接力。

**角色级 shaping（HAPPO/HASAC 阶段追加，缓解异构信用分配）**：

- Scout：发现新资源 `+`、冗余探测 `-`；
- Excavator：入料斗单位 `+`、空跑 `-`；
- Hauler：到 depot 单位 `+`、空载往返 `-`。
- 注意：shaping 项用**势函数（potential-based）**形式，避免改变最优策略。

## 4. 观测与动作编码（角色感知）

### 4.1 每车观测（拼接为一个向量 / 或经注意力聚合）

```
自身：  [x, y, yaw, vx, wz, 载量(bucket/bin), 角色one-hot(3维)]
资源：  相对每处资源的 [dx, dy, 剩余量, 是否被指派]（经注意力/最大池化聚合为定长）
队友：  相对每台队友的 [dx, dy, 角色one-hot, 载量]（经注意力聚合）
目标点： 相对 depot 的 [dx, dy] + 相对当前子目标(会合点/指派资源)的 [dx, dy]
```

- **变长→定长**：资源/队友数量可变，用**自注意力池化**（论文用定长观测、按规模分训；本方案
  用注意力替代分训，适配变资源/变团队）。
- **角色嵌入**：角色 one-hot 经可学习嵌入层，拼入观测与 critic——这就是「角色感知」的最小形态。

### 4.2 动作（沿用 `lunar_env` 的异构动作空间）

```
Scout     : drive=[vx,wz]                      （连续，∈[-1,1]）
Excavator : drive=[vx,wz], tool∈{idle,dig,load}
Hauler    : drive=[vx,wz], tool∈{idle,dump}
```

- 决策层只输出**任务级动作**（去哪/挖/装/运/卸），底层导航与操作由控制器闭环执行。
- HAPPO/HASAC 用异构 actor：连续分量用高斯策略，`tool` 用分类策略。

## 5. 训练课程（冷启动 → 逐步加难）

| 阶段 | 场景 | 目标 |
| --- | --- | --- |
| C0 | 固定 1 资源 + 无会合 + 短距离，Scout 固定、只训 Hauler「去 depot 卸载」 | 验证回报链路 + 调通训练循环 |
| C1 | 1 Excavator + 1 Hauler：挖→装→运→卸（资源位姿已知） | 学会挖掘/会合/接力 |
| C2 | 加入 Scout 探测 + 3 资源区随机 + 指派 | 学会「探测→调度」 |
| C3 | N/M/K 团队规模可变 + 资源分布/障碍随机 + 动态重规划 | 泛化与鲁棒性 |

- 每个阶段从**规则基线的 rollout** 做**示范初始化**（behavior cloning 预热），再转 RL——复用
  Phase 1 的规则基线，避免冷启动。
- 随机化：资源位姿、机器人初始位姿、障碍、种子（对齐论文「每种子随机」）。

## 6. 评估协议与验收

**指标**：交付单位、任务完成时间、能耗、失败/碰撞次数、跨种子均值与方差。

**对比组**：

| 组 | 说明 | 目的 |
| --- | --- | --- |
| 规则基线 | 就近拍卖 + 状态机（Phase 1） | 回报下界 |
| 准共享 MAPPO（无角色） | 参考论文，角色 one-hot 输入但共享 actor | 消融：角色是否共享 |
| 角色感知 MAPPO | 独立 actor + 角色嵌入（无注意力） | 消融：角色嵌入作用 |
| **角色感知 HAPPO/HASAC** | + 三元注意力 | 核心方法 |

**动态重规划**：训练时随机中途「新资源出现 / 资源耗尽 / 队友故障」，验证在线重规划能力
（对应论文在线重规划 + 你 odt 的「适应不同机器人数量与资源分布」）。

**验收（统计显著）**：角色感知 HAPPO/HASAC 交付量 ≥ 规则基线，且 ≥ 无角色 MAPPO。

## 7. 落地实现清单（Phase 2 顺序）

1. **reward 改造**（`lunar_env`）：落地 §3 的 `Δdelivered/吸引/步进/错目标/超时` + 分阶段重加权开关。
2. **观测改造**：落地 §4.1 的角色 one-hot、相对资源/队友/depot、变长注意力池化。
3. **训练脚手架**：Gymnasium + PyTorch，实现准共享 MAPPO（基线）与异构 HAPPO/HASAC（核心）的
   训练循环（rollout/update、CTDE、GAE、策略熵）。
4. **课程与示范**：Phase 1 规则基线的 rollout 存为数据集，做 BC 预热（C0–C2）。
5. **评估脚本**：§6 的四组对比 + 多种子 + 动态重规划。
6. **消融报告**：角色共享 vs 不共享、有无角色嵌入、有无注意力、有无角色级 shaping。
