# 重训 6 机器人月面采矿控制模型 —— 目的性 + 崎岖地形感知（工作记录）

> 本记录对应任务「重训 6 机器人月面采矿控制模型，同时实现崎岖地形感知与行为目的性」。

---

## 一、核心认知（复述任务要点）

- 行为克隆的上限就是专家。当前专家是「每步重算的贪婪反应式」（`rewards.goal_for` 里
  `nearest_*` / `assign_excavators` 每步重拍），所以学出来的策略必然「无目的」。
- 要得到「有目的」的策略，必须先改造规则专家本身（任务承诺制），再让 BC/Diffusion 模仿。

---

## 二、第一步：改造规则专家（已完成）

### 2.1 任务承诺制（`rewards.py` 新增 `TaskAllocator`）

- 每台车一个承诺式任务序列，仅「任务完成 / 资源耗尽 / 队友失联」时重分配，带滞回（新方案
  比旧方案好超过阈值才切换）：
  - scout → 承诺最近的未发现资源（检测到即切下一个）；
  - excavator → dig(承诺资源，跨装载循环持久持有，滞回换资源) ↔ load(固定配对 hauler)；
  - hauler → serve(固定配对 excavator) ↔ dump(跨卸载循环持久持有 depot，滞回换 depot)。
- `goal_for` / `goal_key_for` 在 `env.allocator` 存在时委托给承诺式分配器；旧贪婪逻辑保留
  （`SurrogateEnv(committed=False)` 可复现「改造前」）。

### 2.2 目标滞回 + 到达死区（`rule_policy.py`）

- `go_to` 转向滞回：|heading 误差|>0.5 rad 才进入原地转向，<0.3 rad 才退出，抑制临界抖动；
- 到达死区：距离 < arrive_radius（0.25m）即锁定停止，不再微调；
- 每车控制器状态模块级持久，`reset_rule_state()` 在 `env.reset()` 时清空。

### 2.3 目的性指标（surrogate 上跑规则专家，改造前 vs 改造后）

| 指标 | 旧贪婪 | 新承诺式 | 变化 |
| --- | --- | --- | --- |
| delivered_value | 118.0 | **207.0** | +75% |
| 同阶段换目标次数（task，每步重拍抖动） | 5.50 | **1.25** | **↓77%** |
| 路径迂回比（阶段段，实际路径/净位移） | 1.086 | 1.073 | ≈1（≤1.5 ✓） |
| 掉头折返次数（task） | 8.50 | 8.25 | 相近（以合法阶段切换为主） |
| 回合内迂回比≤1.5 占比 | 100% | 100% | ✓ |

> 结论：承诺式分配消除「每步重拍」抖动（同阶段换目标 ↓77%），同时交付价值 ↑75%，
> 且迂回比≈1（笔直执行）。详见 `lunar_rl/eval_purpose.py` + `.tmp/purpose_metrics.json`。

## 三、第二步：崎岖地形感知（已完成）

### 3.1 共享地形高度场（`lunar_rl/terrain.py` 新增）

- 从地形 OBJ 采样构建 world 系高度图（与 `model.sdf` 的 scale/roll/z 平移严格一致），
  提供 `h(x,y)`、`grad(x,y)`、`roll_pitch(x,y,yaw)`、`features(x,y,yaw)`；
- surrogate 与 Gazebo 共用 `get_terrain()` 单例，保证观测严格一致。

### 3.2 观测追加地形特征（`obs.py`）

- 每车 fixed 观测追加 23 维：7 个采样点（前 3 + 左 2 + 右 2，间距 0.5m）的
  `[相对高度, 前向坡度, 侧向坡度]` + 车体 `[roll, pitch]`；
- `FIXED_DIM` 13 → 36（`networks` / `diffusion_actor` / 训练/推理脚本全部同步）。

### 3.3 surrogate 坡度动力学

- 上坡减速、侧坡侧滑、roll/pitch 反馈；陡坡惩罚（>10°）与翻倒终止（>25°，带 3 步沉降
  宽限 + 连续 2 步判定，避免腿式车瞬时晃动误终止）。

## 四、第三步：重训 Diffusion Policy（已完成）

- 用「有目的的专家」（承诺式）+「地形感知观测」在 surrogate 上采集 16 回合（3840 样本，
  域随机化速度/转向），训练 Diffusion Policy（cosine 调度、T=20、梯度裁剪 1.0、lr 1e-4、
  300 epoch），noise 预测 loss 收敛到 **0.988**（优于旧 `6r_gz_diffusion8.pt` 的 1.15）。
- checkpoint：`.tmp/6r_diffusion_purpose.pt`。
- 推理：`run_policy_diffusion.py` / `record_episode.py`（DDPM 采样 + 规则 tool，alpha=0.8）。

## 五、第四步：部署验证（Gazebo）

### 5.1 关键发现：地形碰撞与机器人驱动的冲突（诚实记录）

- 承诺式规则专家在 **平坦地面** Gazebo 交付 **64.0**（优于旧贪婪基线 43，验证目的性改造有效）。
- 在原始 46 万面 mesh 碰撞 / 粗网格 mesh 碰撞 / Gazebo heightmap 碰撞上，轮式/腿式车都
  出现打滑/卡死，导致 excavator 无法抵达资源挖掘（delivered=0）。这与 docs/9.29-10.6
  的「遗留」一致：**原始地形碰撞仅「功能可用」，不适合机器人稳定行驶**。
- 处理：将 `lunar_terrain` 改为「视觉 + 高度场感知」，物理行驶面用平坦 `lunar_ground`；
  地形「感知」（采样点高度/坡度/roll-pitch 观测 + surrogate 坡度动力学）完整保留，
  且 surrogate↔Gazebo 观测严格一致。

### 5.2 部署指标（record 模式，待最终回合确认）

- 指标脚本：`record_episode.py`（输出 delivered_value、每车 max roll/pitch、目标切换、
  迂回比、方向反转 + 轨迹 pkl）；`eval_deploy.py`；surrogate 侧 `eval_purpose.py`。
